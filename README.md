# Mobility Talk

mobilitytalk.org: a mobility resources and advocacy directory and guide.

A free, national, source-linked site for people with disabilities and the people who help them. It began with mobility barriers (wheelchair and equipment repair, coverage denials, home access, vehicles, transit and public access) and now covers disability broadly: benefits and health coverage, housing, rides, in-home help, work and school, vision and hearing services, rights and crisis lines. It lists programs for all 50 states and D.C., with a first set of listings for the five U.S. territories. It also helps people ask lawmakers for change.

Created and maintained by Travis Vought. Corrections: travis@vethomeguard.org.

## Pages
- `index.html`: home page. It opens with an urgent-help strip, then a grid of sixteen needs and a "who is it for" row (script `assets/home.js` carries the chosen state into the links and stores nothing), then the state and barrier picker for the next-step finder
- `local-help.html`: searchable directory by state or territory, county, type of help and who the program is for (built by `scripts/build_local_pages.py`, reads `data/local-programs.json`, `data/county-veterans-offices.json` and `data/category-guides.json`). With no state chosen it shows national resources and asks for a state
- `know-your-rights.html`: fourteen situations (work, public places, housing, a baby or toddler who may need help, school, health care, transit, air travel, phones, voting, benefit denials, abuse, agency problems, free help), each with who handles it, first steps, contacts and the deadline where the source states one (built by `scripts/build_rights_page.py` from `data/know-your-rights.json`; phone numbers are pulled from the directory records it names)
- `espanol.html`: national lines and resources that serve Spanish speakers, in Spanish (built by `scripts/build_spanish_page.py` from `data/ayuda-espanol.json`; every number is pulled from the directory record it names, and each item records the evidence that the line serves Spanish speakers). The Spanish text has not yet been reviewed by a fluent speaker, and the page says so. Every English page links to it from the main navigation
- `about.html`: who runs the site, sourcing, privacy, what has and has not been done for accessibility, and how to report a barrier (hand-written)
- `ramps-home-access.html`: who pays for or provides ramps and home changes, with VA grant and Ohio waiver preparation checklists (`data/home-access-checklists.json`)
- `mobility-rights.html`: step-by-step finder (built from `templates/mobility-rights.html` and `data/mobility-routes.json`)
- `disability-advocacy.html`: five advocacy issues with state and federal message builder (built from `templates/disability-advocacy.html` and `data/disability-advocacy.json`)
- `mobility-independence.html`: repair and adapt equipment actions

## Kinds of help and who a program is for

`scripts/extract_local_programs.py` assigns each record one of seventeen kinds of help (`categories` in the data file) and a list of `audience` tags (`audiences`). Six kinds were added in November 2026: crisis, safety and mental health; income, benefits and health coverage; in-home help, food and daily living; housing; work, school and training; vision, hearing and communication. A seventeenth, babies, children and school, was added the same month for early intervention and Parent Centers. Existing families are moved by rule in that script (blind agencies, talking-book libraries, relay and phone-equipment programs to vision and hearing; vocational rehabilitation to work), so a re-extract keeps them there.

Audience tags come from the program family and the program name, or from an explicit `audience` list on a record in `data/added-programs.json`. A record with no tag serves people with any disability. Three optional fields on added records shape the lists: `sort` pins a record to the top of its group (988 leads the crisis list), `hide_if_state_has` lets a national pointer step aside once the chosen state's own office is listed, and `link_kind` overrides the label on the main link.

`data/category-guides.json` holds, for each kind of help, the button label, a one-line description and the "Before you call" lists (what to have ready, what to ask). The directory page and the state pages both read it. They are general reminders written for this site, not rules of any program.

Territories (`TERRITORIES` in `scripts/build_mobility_routes.py`) appear in the directory and have their own pages. The law finder, the letter builder and the printed help list cover the 50 states and D.C.

`docs/GAP-AUDIT-2026-11-15.md` records the review that led to these changes and lists what is still missing.

## Partner page

`partner.html` lets visitors share the directory, print a handout, sponsor it at three flat yearly levels, give, or tell us how they help. There are no commissions: nobody is paid a percentage of gifts or sponsorships, and people who introduce a sponsor are thanked by name instead. Inquiries go by email; `assets/partner.js` only builds copyable links in the page and stores nothing. The give button is a PayPal donate link to Veteran Home Guardians, built in `assets/partner.js` so the account address is not written in the page source; replace it with a PayPal hosted button ID if one is created. Gifts and sponsorships are described as received by Veteran Home Guardians. `handout.html?state=XX` (script `assets/handout.js`) builds a printable help list for any state from the statewide records that have a phone number, plus national hotlines.

## State pages

`scripts/build_state_pages.py` writes `states/<state>.html` for all 50 states, D.C. and the five territories, plus `states/index.html`. Each page lists every non-veterans program for that state as plain HTML (statewide programs as cards, county programs as a compact list), so search engines and people without JavaScript can read them. The pages are generated from `data/local-programs.json`; do not edit them by hand. `npm run build` regenerates them and adds them to `sitemap.xml`. `tests/states.cjs` checks every record is present, no other state's records leak in, and links and metadata are valid. `tests/front-door.cjs` checks the home page need grid, the rights page against the directory records, the about page and the sourcing of the November 2026 records; `tests/front-door-browser.cjs` checks widths down to 320 px, focus, the no-JavaScript paths and that nothing is stored.
